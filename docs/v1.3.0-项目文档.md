## 1. 项目情况

### 1.1 项目定位

AutoCICD 是一个**图形化 CI/CD 流水线自动搭建平台**。用户通过浏览器表单填写项目信息，平台自动完成：

1. **生成**目标 CI/CD 工具的流水线配置文件（YAML / Jenkinsfile / Dockerfile 等）
2. **推送**配置文件到目标代码仓库
3. **连接**目标服务器（支持多跳/堡垒机/零信任链路）
4. **安装** CI/CD 工具（Jenkins / GitLab Runner）
5. **配置**流水线 Job、部署凭据、Secrets/CI Variables
6. **WebSocket 实时反馈**每一步的执行进度与日志

### 1.2 能力矩阵（v1.3.0）

| 维度 | 支持范围 |
|------|----------|
| **流水线工具（7 种）** | Jenkins、GitHub Actions、GitLab CI、GitLab Runner、阿里云效、华为云 CodeArts、腾讯云 CODING |
| **项目类型（7 种）** | Java Maven、Java Gradle、Vue.js、React、Python、Go、**Android（v1.3.0 新增）** |
| **部署方式（4 种）** | Docker 部署、直接部署、应用服务器（TongWeb/Tomcat）、**应用分发（Android，v1.3.0 新增）** |
| **SSH 认证** | 密钥认证（id_rsa）、密码认证（sshpass，自动安装） |
| **网络链路** | 直连、多跳链路（中继/堡垒机/零信任网关）、隔离网络 |
| **流水线模式** | Release 发布模式（审批+合并+回滚）、Integration 集成测试模式（临时合入不污染主干） |
| **高级部署** | 多环境部署（多分支+独立服务器）、负载均衡滚动部署（Nginx upstream） |

### 1.3 技术架构

```
┌─────────────────┐    HTTP/WebSocket    ┌──────────────────────┐
│  Vue 3 前端 SPA  │ ◄──────────────────► │  FastAPI 后端服务      │
│  (Vite 构建)     │                      │                      │
└─────────────────┘                      │  ├─ 配置生成器(7工具)  │
                                          │  ├─ 流水线编排引擎     │
┌─────────────────┐                      │  ├─ Git 操作(git_ops) │
│  桌面端打包入口    │                      │  ├─ SSH 操作(ssh_ops) │
│  (pywebview)     │                      │  └─ 云 API 客户端      │
└─────────────────┘                      └──────────────────────┘
```

- **后端**：Python 3.11 + FastAPI + WebSocket（实时进度推送）+ paramiko（SSH）
- **前端**：Vue 3 + Vite，单文件组件，无状态管理库
- **桌面分发**：PyInstaller 打包三平台二进制（Linux / macOS / Windows），pywebview 桌面应用
- **离线能力**：bundled-tools 目录内置 JDK、Docker、Jenkins war 等离线安装包，支持内网/信创环境

### 1.4 项目结构

```
auto-cicd/
├── backend/
│   ├── main.py                 # FastAPI 入口（REST + WebSocket）
│   ├── generators/             # 7 个工具的配置生成器
```

## 2. 使用方法

### 2.1 环境要求与启动

**环境要求**：Python 3.10+、Node.js 18+

```bash
# 1. 克隆项目
git clone https://github.com/tianlanshuilan/autocicd.git
cd autocicd

# 2. 启动后端（端口 8000）
cd backend
pip install -r ../requirements.txt
python main.py

# 3. 启动前端（端口 3000）
cd frontend
npm install
npm run dev

# 4. 浏览器打开 http://localhost:3000
```

也可直接下载 GitHub Release 中的三平台二进制文件（自动构建产物），双击运行即可。

### 2.2 两种使用模式

| 模式 | 说明 |
|------|------|
| **仅生成** | 只生成配置文件，前端展示/下载，不执行推送和部署 |
| **自动搭建** | 完整执行：克隆仓库 → 生成配置 → 推送 → 连接服务器 → 安装工具 → 配置流水线 → 写入 Secrets |

### 2.3 表单填写步骤（9 步）

1. **流水线工具**：7 种工具卡片选择（华为云/腾讯云标注"配置生成，需手动导入"）
2. **项目类型**：7 种类型卡片选择（新增 Android 🤖）
3. **部署方式**：
   - Docker 部署 / 直接部署（所有类型）
   - 应用服务器 TongWeb/Tomcat（仅 Java）
   - **应用分发（仅 Android，选择 Android 后自动切换）**
4. **项目信息**：仓库地址（自动提取项目名）、分支、端口、JDK/Node 版本
5. **Git 认证**：密码 / SSH 密钥
6. **目标服务器**：地址、端口、认证方式（密码/密钥）、部署路径
   - Android + 云托管工具时此区显示"不需要部署目标服务器"提示
7. **网络访问链路**（可选）：多跳配置（中继/堡垒机/零信任）
8. **云服务凭据**：
   - 阿里云效/华为云/腾讯云：AccessKey 模式（含区域下拉）
   - GitHub/GitLab：Personal Access Token 模式（自动写入 Secrets/Variables）
9. **高级配置**：流水线模式（Release/Integration）、多环境、负载均衡、依赖仓库、国内镜像

### 2.4 Android 应用流水线（v1.3.0 新增）

选择 **🤖 Android** 项目类型后：

| 配置项 | 说明 |
|--------|------|
| 分发平台 | 蒲公英 (pgyer.com) 或 Firebase App Distribution |
| 蒲公英 API Key | 登录蒲公英 → 账户信息 → API 信息 → API Key |
| Firebase App ID | 格式 `1:123456789:android:abcdef` |
| Firebase 凭据 | Service Account JSON 内容 |
| 签名密钥库 | keystore.jks 的 Base64 编码（`base64 -i app/keystore.jks \| pbcopy`） |

**生成的流水线行为**：

- **构建**：`./gradlew assembleRelease`（自动配置 JDK 17 + Android SDK）
- **测试**：`./gradlew test`
- **产物**：`app/build/outputs/apk/**/*.apk` + `app/build/outputs/bundle/**/*.aab`
- **分发**：CI 成功后自动上传 APK 到所选分发平台
- **无需服务器**：云托管工具（GitHub/GitLab）下整个流程在平台 Runner 上完成

**各工具产物**：

| 工具 | 生成文件 |
|------|----------|
| GitHub Actions | `.github/workflows/ci.yml`（构建测试）+ `distribute.yml`（应用分发） |
| GitLab CI | `.gitlab-ci.yml`（build/test/distribute 三阶段，自动安装 Android SDK） |
| Jenkins | `Jenkinsfile`（Setup Android SDK → Build → Test → Distribute） |

### 2.5 凭据与密钥写入

自动搭建时，以下敏感信息会通过云 API 自动写入（需 PAT/Token），否则提示手动配置：

| Secret 名称 | 用途 |
|-------------|------|
| `SERVER_SSH_KEY` | 目标服务器 SSH 私钥（deploy 阶段免交互登录） |
| `SERVER_PASSWORD` / `SSHPASS` | 目标服务器密码（sshpass 模式） |
| `DEP_REPO_TOKEN` | 独立依赖仓库访问凭据 |
| `PGYER_API_KEY` | 蒲公英分发 API Key（Android） |
| `ANDROID_KEYSTORE_BASE64` | Android 签名密钥库 |
| `FIREBASE_APP_ID` / `FIREBASE_CREDENTIALS` | Firebase 分发凭据（Android） |

### 2.6 SSH 双认证模式

生成的流水线支持两种服务器认证方式（自动识别）：

- **密钥模式**：将 `SERVER_SSH_KEY` 写入 `~/.ssh/id_rsa`，`AUTH_PREFIX` 为空
- **密码模式**：自动安装 `sshpass`，`AUTH_PREFIX=sshpass -e`，所有 `ssh`/`scp` 命令统一加 `$AUTH_PREFIX` 前缀

> ⚠️ 密码认证需要目标服务器安装 sshpass，生产环境建议使用 SSH 密钥认证。

### 2.7 连接已部署的 CI/CD 工具（v1.3.1 新增）

若 Jenkins / GitLab Runner **已经部署并运行**，无需重新安装。在「8. CI/CD 工具部署位置」选择 **🔗 已部署的工具**，填写：

| 配置项 | 说明 |
|--------|------|
| Jenkins 地址 | 如 `http://10.0.0.5:8080`（Runner 则填 GitLab 地址） |
| 管理员账号 | Jenkins 登录用户名（默认 admin） |
| 认证方式 | 登录密码 或 API Token（用户 → Configure → API Token） |
| 跳过 TLS 校验 | 仅自签名 HTTPS 证书的内网 Jenkins 勾选 |

**执行行为**：

- **跳过** `ssh_connect` 工具安装 与 `install_tool` 安装步骤（仅在部署目标服务器准备运行环境）
- 通过 **Jenkins HTTP REST API** 连接现有实例：
  - 注入部署目标凭据 `deploy-server-cred`（SSH 私钥或用户名/密码）
  - 注入 Git 仓库凭据 `git-repo-cred`（私有仓库）
  - 创建/更新 Pipeline Job（从仓库 SCM 读取 Jenkinsfile）
- 生成的 Jenkinsfile 首部自动加入 **Prepare Deploy Credentials** 阶段：
  - 密钥认证 → 从凭据写出 `~/.ssh/id_rsa`，后续 `ssh` 免密登录
  - 密码认证 → 安装 sshpass，`SSHPASS` 由 `credentials('deploy-server-cred')` 绑定，命令加 `sshpass -e` 前缀
- **Runner 已注册** 场景：配置推送到仓库后即自动生效，无需额外操作

> 依赖插件：现有 Jenkins 需安装 `credentials-binding`、`ssh-credentials`、`git`、`workflow-aggregator`（多数标准安装已含）。

### 2.8 表单校验与缺失提示（v1.3.1 新增）

执行按钮（生成配置 / 开始搭建）在必填项不全时禁用，并在按钮旁实时提示 **「还需填写：xxx、yyy」**，配置完整时显示绿色 **「✅ 配置完整」**。点击时若仍有缺失，会滚动到顶部并列出具体缺少的字段，不再出现「点击无反应」。

## 3. 配置推送流程

自动搭建模式下，平台按 8 个步骤顺序执行（WebSocket 实时回传进度）：

```
Step 1  git_clone          克隆目标代码仓库到临时工作目录
Step 2  branch_select      选择/确认集成分支（多分支时弹窗）
Step 3  generate_config    调用对应生成器产出配置文件（含本地依赖检测）
Step 4  git_push           将配置文件提交并推送到目标仓库的指定分支
Step 5  ssh_connect        通过跳转链路连接工具安装服务器
                           （Android + 云托管工具自动跳过）
Step 6  install_tool       安装 Jenkins / GitLab Runner（含离线包、国内镜像）
                           并准备部署目标服务器运行环境（Docker/语言运行时）
Step 7  configure_pipeline 创建 Jenkins Job / 注册 Runner / 注入部署凭据
Step 8  configure_cloud    云托管工具：写入 Secrets/CI Variables
                           （GitHub PAT / GitLab Token / 阿里云效 AccessKey）
```

### 3.1 推送细节

- 使用表单中填写的 Git 凭据（密码或 SSH 密钥）完成 push
- 配置文件提交信息格式：`chore: add CI/CD pipeline configuration (auto-cicd)`
- 推送成功后，GitHub Actions / GitLab CI 流水线**自动生效**（随仓库配置文件）
- Jenkins 需要通过 CLI 创建 Job（自动完成），轮询 SCM 或 Webhook 触发

### 3.2 凭据弹窗机制

执行过程中若缺少必要凭据（如服务器密码、Runner 注册 Token），引擎会通过 WebSocket 向前端发起 `request_credential` 请求，前端弹窗收集后回传，流程无中断继续。

## 4. 自动构建（本项目自身的 CI）

本项目使用 GitHub Actions 实现自身的持续集成与发布：

### 4.1 构建流水线

| Workflow | 触发条件 | 作用 |
|----------|----------|------|
| `.github/workflows/build.yml` | 推送 `v*` 标签 / 手动触发 | 三平台 CLI 二进制构建 + Release |
| `.github/workflows/build-desktop.yml` | 推送 `v*` 标签 / 手动触发 | macOS DMG / Windows 安装包构建 |

### 4.2 build.yml 流程

```
1. 矩阵构建（ubuntu-latest / macos-latest / windows-latest）
   ├─ Python 3.11 + Node.js 22
   ├─ pip install -r requirements.txt + pyinstaller
   ├─ npm ci && npm run build（前端产物嵌入后端）
   ├─ pyinstaller auto-cicd.spec --clean --noconfirm
   └─ 上传产物（保留 30 天）

2. Release（仅标签触发）
   ├─ 下载三平台产物
   ├─ 重命名为 auto-cicd-{linux|macos|windows}-x64
   └─ softprops/action-gh-release 创建 Release + 自动生成发行说明
```

### 4.3 发布流程

```bash
# 1. 提交代码并推送
git add -A && git commit -m "..." && git push

# 2. 打版本标签并推送（自动触发构建 + Release）
git tag v1.3.0
git push origin v1.3.0

# 3. 在 GitHub Actions 页面观察构建进度
# 4. 构建完成后在 Releases 页面下载三平台二进制
```

### 4.4 产物清单

| 产物 | 说明 |
|------|------|
| `auto-cicd-linux-x64` | Linux 单文件二进制（PyInstaller onedir→onefile） |
| `auto-cicd-macos-x64` | macOS 可执行文件 |
| `auto-cicd-windows-x64.exe` | Windows 可执行文件 |
| `AutoCICD-Installer.dmg` | macOS 桌面应用安装包（build-desktop.yml） |

## 6. 常见问题

### Q: 华为云/腾讯云为什么标注"需手动导入"？

A: 这两个平台的流水线 API 鉴权复杂且区域差异大，当前仅生成标准配置文件，需要在控制台手动导入 YAML。GitHub/GitLab/阿里云效支持全自动。

### Q: Android 项目需要自己的服务器吗？

A: 不需要。选择云托管工具（GitHub Actions / GitLab CI）时，构建和分发全部在平台 Runner 完成。仅当选择自建 Jenkins/Runner 时才需要服务器安装 CI 工具。

### Q: 密码认证为什么提示安装 sshpass？

A: 生成的流水线在 Runner 上用 `sshpass -e` 读取 SSHPASS 环境变量完成免交互登录。生产环境建议改用 SSH 密钥认证。

### Q: Keystore 如何传给 CI？

A: 前端表单粘贴 Base64 编码内容 → 平台写入 `ANDROID_KEYSTORE_BASE64` Secret → CI 中 `base64 -d` 解码还原为 `app/keystore.jks`。

### Q: 如何手动触发本项目自动构建？

A: GitHub 仓库 → Actions → Build Cross-Platform → Run workflow；或推送 `v*` 标签。

### Q: 内网/信创环境能用吗？

A: 可以。勾选"使用国内镜像源"，并将离线安装包放入 bundled-tools/ 目录（JDK、Docker、Jenkins war 等），引擎自动检测并走离线安装路径。
